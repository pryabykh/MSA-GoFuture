### <a name="_b7urdng99y53"></a>**Название задачи: определить нефункциональные требования**

### <a name="_uanumrh8zrui"></a>**Дата: 07 мая 2026**

### <a name="_3bfxc9a45514"></a>**Контекст**

Переход от монолита к микросервисной архитектуре требует обеспечения стабильности, масштабируемости и высокой
доступности.

### <a name="_3bfxc9a45514"></a>**Требования**

- Производительность: обработка ≥500k конкурентных поездок.
- Масштабируемость: горизонтальное автоматическое масштабирование сервисов в нескольких регионах.
- Доступность: ≥99,95% uptime критических сервисов.
- Разработка: время выхода на рынок новых функций ≤2 недели.
- Надёжность: MTTR ≤1 час.
- Безопасность: соответствие локальным регуляторным требованиям.
- Обратная совместимость: новые сервисы не должны ломать существующие приложения.
- Observability: полный сбор метрик, логов и алертов, визуализация метрик и рассылка важных уведомлений о работе
  сервисов.
- Интеграции: поддержка внешних систем (платежи, карты, push-уведомления, банки).

### <a name="_3bfxc9a45514"></a>**Решение**

- Внедряем Event Bus (шину) для асинхронного взаимодействия сервисов
- Выделяем доменные сервисы по бизнес-доменам (Booking, Driver, Pricing, Geography, Payments, Notification, Fraud,
  Analytics).
- BI и аналитика через ClickHouse + DataLens/Looker.
- Внедряем API Gateway + Auth Service.

### <a name="_3bfxc9a45514"></a>**Компромиссы**

Event-driven подход добавляет небольшую задержку при обработке событий, но упрощает масштабирование.
