### <a name="_b7urdng99y53"></a>**Название задачи: определить план миграции данных**

### <a name="_uanumrh8zrui"></a>**Дата: 07 мая 2026**

### <a name="_3bfxc9a45514"></a>**Контекст**

Каждый новый сервис должен работать со своей БД, при этом данные из монолита нужно перенести с минимальным простоем.

### <a name="_3bfxc9a45514"></a>**Требования**

- Сохранение целостности данных.
- Возможность синхронизации данных в реальном времени.

### <a name="_3bfxc9a45514"></a>**Решение**

| Сервис         | План миграции                                                                  |
|----------------|--------------------------------------------------------------------------------|
| Booking        | Постепенное копирование данных из монолитного приложения в новую Booking DB    |
| Driver         | Копирование данных о водителях.                                                |
| Pricing        | Копирование исторических данных о ценах. ML-модели обучаются на старых данных. |
| Payments       | Копирование данных о платежах и транзакциях.                                   |
| Geography      | Копирование данных об историях поездок.                                        |
| Notification   | Копирование данных об отправленных пользователям уведомлениям                  |
| Fraud          | Копирование данных о прошлых фрауд проверках                                   |
| Analytics / BI | Копирование аналитических данных                                               |

### <a name="_3bfxc9a45514"></a>**Альтернативы**

- Полная блокировка работы приложения для выполнения разовой миграции всех данных.
  Отказались из-за длительного простоя приложения.

### <a name="_3bfxc9a45514"></a>**Компромиссы**

- Event Bus добавляет небольшую задержку в синхронизации данных.
- Необходимость управления дубликатами и версионирование данных.
