### <a name="_b7urdng99y53"></a>**Название задачи: определить механизмы обратной совместимости**

### <a name="_uanumrh8zrui"></a>**Дата: 07 мая 2026**

### <a name="_3bfxc9a45514"></a>**Контекст**

Сервисы выделяются из монолита по доменам, при этом приложения клиентов должны продолжать работать без изменений.

### <a name="_3bfxc9a45514"></a>**Требования**

- API старого монолита должны оставаться доступными до полного переноса.
- Новые сервисы должны интегрироваться через Event Bus.

### <a name="_3bfxc9a45514"></a>**Решение**

- API Gateway проксирует запросы к монолиту или новому микросервису.
- Event Bus: все события, метрики и логи передаются в брокер сообщений независимо от источника (монолит или микросервис).
- Дублирование данных для чтения, где это необходимо, через Event Bus для постепенного перехода микросеврисов на свои БД.


### <a name="_3bfxc9a45514"></a>**Компромиссы**

- Возможно дублирование данных до полной миграции на микросервисы.
- Повышенная нагрузка на Event Bus, необходимо мониторить производительность и задержки данного микросервиса.
